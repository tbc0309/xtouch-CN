# 内部配置与 SD 同步

简体中文 | [English](STORAGE.en.md) | [README](../README.md)

## 存放位置

配置存放在 128KiB SPIFFS 分区，与两个 OTA 程序分区独立。内部文件系统的可用容量略小于分区原始容量。

| 配置 | 内部路径与 SD 备份路径 |
| --- | --- |
| Wi-Fi、单台或多台打印机、开机默认设备 | `/xtouch.json` |
| 语言、亮度、休眠、风扇、OTA 等设置 | `/xtouch/settings.json` |
| 触摸校准参数 | `/xtouch/touch.json` |
| 屏幕方向 | `/xtouch/hardware.json` |

首次启动需要插入含有效 `xtouch.json` 的 SD 卡。有效配置和已有校准会导入内部存储；之后可以拔卡启动、连接打印机、切换设备和保存设置。已有内部校准时不会每次开机重新校准。

首次导入时读取内部 `/eeprom.bin` 中的屏幕方向。仅在配置分区完全空白时创建文件系统；已使用的配置区挂载失败时显示错误，保留原有数据。

## SD 卡文件

| 文件 | 用途 | 是否同步到内部 |
| --- | --- | --- |
| 根目录 `xtouch.json` | Wi-Fi 和最多 100 台打印机 | 是 |
| `xtouch/settings.json` | 语言、亮度、休眠、风扇、OTA 开关 | 是 |
| `xtouch/touch.json` | 本机触摸校准；删除后需重新校准 | 是，含删除状态 |
| `xtouch/hardware.json` | 屏幕方向 | 是 |
| `xtouch/ota.json` | 下载固件的临时清单 | 否；更新检查或安装后删除 |
| 根目录 `firmware.bin` | 卡刷待安装的应用固件 | 否；安装处理后删除 |
| `*.bak` | 首次导入原版配置时的原始文件 | 保留在 SD，不参与自动覆盖 |
| `*.previous` | 上一次正常保存的滚动备份 | 每个存储介质独立维护 |
| `*.conflict` / `*.invalid` | 最近一次冲突或无效输入备份 | 不参与自动加载 |
| `*.tmp` / `*.part` | 写入、下载中间文件 | 非运行必需文件，不同步 |

固件同步表中四个配置文件，临时文件和其他文件不参与配置同步。完成初始化后，正常运行无需 SD 卡。确认配置正常后，可清理不需要的备份。触摸校准参数仅适用于对应设备。

## 原版配置升级

首次导入原版 JSON 时，先在原路径旁保留原始 `.bak`，核验备份后才写新版。已有 `.bak` 不被日常保存覆盖；后续保存使用 `.previous`。单设备 `mqtt` 自动转为 `printers` 的第一个槽位，保留 Wi-Fi、访问码、序列号、机型和其他原有字段，设置 `activePrinter: 0`。原版亮度、休眠、风扇设置和有效触摸校准同样导入。缺少语言时默认简体中文。

备份失败时不覆盖原 SD 文件；请更换可写 SD 卡后重试。原始备份也包含连接凭据，不要上传。
## 插卡后的选择规则

各配置文件独立比较，普通情况下在约 10 秒内发现插卡；用户刚操作屏幕时暂缓探测。板子没有卡检测引脚，空槽使用短 SPI 命令探测，避免 SD 驱动在空卡槽反复重试。

JSON 中的 `_storage` 由固件管理，包含版本、内容摘要、修改时间与同步标记。用户编辑 Wi-Fi 或打印机参数时保留或删除这块均可，不需要手动修改它。

1. 内部没有有效配置时，导入有效 SD 配置。
2. 内容相同不重复导入；有待同步修改时补齐备份。
3. 两边修改时间都可信且相差超过 FAT 的约两秒精度时，使用较新的内容。
4. 尚未联网校时、日期相同或无法确定先后时，优先保留内部尚未同步的修改；否则接受 SD 中被手动编辑的有效配置，或较新的版本。
5. 冲突时保留一份最近的 `.conflict`；损坏的 SD JSON 尽量保留为 `.invalid`。无法备份的超大或不可写文件不会强行覆盖。

设备在连接 Wi-Fi 后通过 NTP 获取时间；没有可信时间不会把 1970 年当作修改日期。此时使用版本及待同步标记，日期同步后补记时间。不同步时钟的离线编辑无法绝对判断先后，因此冲突备份应保留到确认配置正确。

插卡导入了新的配置后会自动重启，按同一份完整配置启动；普通 SD 备份回写不会重启。无效的 Wi-Fi、打印机或校准 JSON 不会替换有效的内部配置。

## 保存顺序

设置改变时先写内部临时文件，读回校验成功后提交，再同步覆盖 SD 备份。无卡或卡写入失败时，内部变更保留为待同步状态。相同内容不重复写入 Flash，也不增加版本号。

内部和 SD 都采用临时文件、校验与备份后改名。日常保存轮换 `.previous`；启动发现内部主文件损坏或在改名过程中断电，会尝试恢复上一份有效 `.previous`（也可读取早期 `.bak`）。保存失败不会把不完整 JSON 当作新配置。

重置触摸校准会写删除标记；没有 SD 卡时重置，日后插卡也不会把旧校准重新导入。

## 固件更新

SD 根目录的 `firmware.bin` 用于卡刷更新；插卡检测到可识别的应用镜像时会重启进入安装流程。没有清单的手动更新检查 ESP 镜像格式与分区大小，有 OTA 清单时还校验长度和 MD5。更新成功后清除暂存文件。

无 SD 卡时，在线 OTA 的小型清单暂存在内部文件系统，应用流式写入备用程序分区；完整下载、MD5 和 ESP 镜像校验通过后才切换启动分区。失败会中止安装，继续运行原程序，配置区不随应用更新覆盖。详见 [更新与维护](UPDATING.md)。

若配置区已损坏并提示无法挂载，先保留 SD 备份，再按当前分区表仅擦除 `0x3D0000` 起的 `0x20000` 字节配置区，重新启动后从 SD 恢复；不要在未备份时全盘擦除。USB 工具的全盘擦除也会清空内部配置。

配置包含 Wi-Fi 密码和打印机访问码；内部存放不等同于启用 Flash 加密。不要公开分享 SD 配置和配置备份。
